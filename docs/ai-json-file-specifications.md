# SplatWorks and DrawSplat JSON file specifications for AI chatbots

Reference revision 1.0 · 30 October 2026 · Application source verified at commit `7c3e452a6c82a609bd6356ccbb2415643a5c579b` (v3.1.46). File-format versions below are independent of suite/package versions.

Upload this **one Markdown file** to your chatbot together with your source content. Tell it the target tool, desired activity/document, learner level, and desired output filename. The chatbot should follow only the matching profile and return a separate importable JSON file. This reference is instructions; it is not itself a native project to import into an app. No account credentials, API key or subscription is needed to use the reference.

These profiles describe supported JSON imports, concrete generation rules, and complete examples. “Valid JSON” alone does not prove an app can open a file or that every line fits a page. The generation contract and verification section define the checks needed before calling a file ready.

## Copy this prompt into your chatbot

> Use the attached SplatWorks and DrawSplat JSON file specifications as the format authority. Target tool: [NAME]. Create [ACTIVITY OR DOCUMENT] from the content I provide. Intended audience: [GRADE OR AUDIENCE]. Follow the exact markers, native field names, types, units, references, and importer behavior for that tool. Replace the sample content with mine; retain necessary wrappers and defaults. Do not create an invented common SplatWorks schema. Return a downloadable file with the documented extension and valid UTF-8 JSON. If you cannot attach a file, return one raw JSON code block and its exact filename. Validate syntax and cross-references; if execution is available, test with the documented importer or validator. Identify any checks you could not run, media I must supply, and UI settings the importer does not restore. If the requested tool has no JSON import, say so and use a documented supported alternative rather than pretending that a JSON project is importable. Ask only for content or assets that are genuinely missing.

## Universal generation contract

1. Choose exactly one app profile per output. Do not wrap a project in a schema document, in an array of files, or in the chatbot’s message envelope. Do not add JSON Schema’s `$schema` as an app identity marker.
2. Write UTF-8 JSON with double-quoted keys and strings, no comments, no trailing commas, no undefined/NaN/Infinity, and no duplicate keys. Use actual booleans, numeric values and null where the profile requires them. JSON has no Date, Blob, Map, function or Set types.
3. Escape quotes/backslashes correctly. Encode newlines inside JSON strings as `\n`; do not insert literal unescaped line breaks. Markdown fences belong in the chat fallback, never inside the saved .json file.
4. Preserve exact app/type/schema markers and numeric versus string versions. `WriteSplatTM`, `ListSplatTM`, `LayoutSplat`, `PlanSplat`, and `FontSplat` are different literal identities. Filename suffixes alone do not convert formats.
5. Generate stable unique IDs and resolve every cross-reference, including records, frames, stories, assets, connectors, layouts and clips. Do not confuse display labels with IDs. Preserve IDs when updating an existing project; use new IDs for distinct new objects.
6. Use complete required containers even when empty. Do not place sample ellipses, placeholders like `...`, pseudo-code, or explanatory sentences into output JSON. The complete examples below may be copied and adapted.
7. Follow each tool’s units. LayoutSplat uses points; ShowSplat uses a 1600×900 pixel canvas; timeline times are seconds; FontSplat image placements are artwork-relative. GridSplat’s cells are strings, while ListSplat numbers are numbers.
8. Use real supplied media bytes or supported URLs only. Never invent base64, font data, hashes, durations or missing images. A `blob:` URL and a chatbot’s temporary file path will not travel with the JSON. Ask for real assets or omit optional media.
9. Match the user’s content faithfully. Leave citations empty when none were supplied; do not invent source attributions or standards codes. Check question answers, distractors, formulas, word counts and date/time values as well as structural validity.
10. Before delivery: parse the final bytes, verify required keys/enums/ranges and referenced IDs, test in the target app when possible, then inspect the rendered result for clipping, text overflow and missing media. State the actual checks performed; do not call an untested file “perfect” or claim that media was generated by metadata alone.

## 1. DrawSplat Whiteboard

**Open:** https://splatworks.org/app/whiteboard.html  
**Filename example:** `water-cycle.drawsplat.json`  
**Import:** Use the whiteboard’s local JSON open/load control (Open from device).

Root: `version` is the whiteboard’s string `"3.1.12"`, not the suite release number; `title`, `className`, `studentName` are strings; `mode` is `"teacher"` for this authoring profile; `assignmentMode` boolean; `currentLayer` `"shared"`; `restorePoints` array; `showAnswerKey` boolean; `active` zero-based panel index; `panels` nonempty array. Use unique string IDs for panels and objects. A panel has `id`, `name`, `bg`, `objects`; `bg:"blank"` is safe. There are no root `slides` or `pages` fields.

Basic object fields: `id`, `type`, numeric `x,y,w,h`, `locked` boolean, `layer` (`shared`, `teacher`, `student`), `stroke` CSS color, `strokeWidth` number, `fill` CSS color or `"none"`, `fillPattern:""`, `opacity` 0–1. Text-capable types include `text`, `sticky`, `comment`, `rect`, `ellipse`, `diamond`, `triangle`, `callout`, `speech`, `polygon`, `star`. Include `text` and matching escaped HTML in `html` (plain `<p>`/`<br>` is sufficient); `textColor`, `fontSize`, `hAlign` left/center/right, `vAlign` top/middle/bottom, `textRotation`, `autoScaleText`. Omit `html` to let plain text migrate; never put different content in the two fields. Do not use the literal placeholder strings “Text” or “Type here” as intended content: legacy cleanup can remove them.

Use modest coordinates, for example x=60–1000 and y=60–650, then inspect the board. A connector uses `type:"connector"`, existing `fromId` and `toId` in the same panel, `fill:"none"`, and optionally `connectorLabel`, `connectorLabelSize`, `connectorLabelColor`. Freehand paths use SVG path text in `d`, not an array of points. Images use actual `src` image data and numeric geometry. Media/widget subtypes have additional app-specific fields; reuse an actual export rather than inventing those structures. New files should have empty restore-point history, not copied account or recording state. Migration creates a recording-board ID if omitted and updates the version string. Geometry must be finite numbers. Board file size must be at most 64 MiB. Imported panels and objects are rendered, not an arbitrary scene graph from another drawing library.

## 2. WriteSplat

**Open:** https://splatworks.org/splatworks/writesplat/  
**Filename example:** `water-cycle.writesplat.json`  
**Import:** File → Open native WriteSplat file.

Required marker: `app:"WriteSplatTM"` (literal letters TM), numeric `version:1`. Root `createdAt`, `updatedAt` ISO timestamp strings; `metadata:{title,author,targetGrade}` with string values (grade is a string); `document:{format:"prosemirror-json",content:...}`; `teacher:{studentView:boolean,citations:string[],answerKey:string[]}`. Preserve these complete wrappers.

The editor uses ProseMirror basic/list/table names, **not Tiptap camelCase**: `doc`, `paragraph`, `heading` (`attrs.level` 1–6), `text`, `hard_break`, `horizontal_rule`, `blockquote`, `code_block`, `bullet_list`, `ordered_list` (`attrs.order`, default 1), `list_item`, `image`, `table`, `table_row`, `table_cell`, `table_header`, `page_break`, `tab`, `teacher_only_block`. A doc contains block nodes. A list contains list_item nodes; each list_item starts with a paragraph. A table contains rows containing cells; cells contain paragraphs. Text nodes have a nonempty `text` string and cannot have children. For an empty paragraph use `{ "type":"paragraph" }`, not a text node containing an empty string.

Text marks are `strong`, `em`, `code`, `link` (`attrs.href`, optional title), `underline`, `strike`, `cloze` (`attrs.answer`), `teacherOnly`, `fontFamily` (`attrs.family` string), `fontSize` (`attrs.size` CSS string such as `"14pt"`), `textColor` and `highlight` (`attrs.color`). **Do not use `bold`, `italic`, `textStyle`, `bulletList`, or `tableCell` as schema names.** Paragraph/heading optional attrs include `align`, numeric point-valued `fontSize`, `leading`, `spaceBefore`, `spaceAfter`, `indentLeft`, `indentRight`, `firstLineIndent`, `fontFamily`, `lineMultiple`, and ascending numeric `tabs`. Image attrs follow ProseMirror (`src`, `alt`, `title`); use real embedded image bytes for portability. Standard table-cell attrs are `colspan`, `rowspan`, `colwidth` (null or widths array). Keep simple nonmerged tables unless the grid is validated.

`document:{format:"html",body:"<p>...</p>"}` is an accepted legacy import and is migrated, but generate the native ProseMirror profile above. `customFonts` is optional and needs real licensed font data; omit it for standard fonts. Teacher-only flags affect the app’s presentation; they are not file encryption.

## 3. GridSplat

**Open:** https://splatworks.org/splatworks/gridsplat/  
**Filename example:** `water-cycle.gridsplat.json`  
**Import:** File → Import spreadsheet file; choose the .gridsplat.json file.

Root `version:1`, `metadata:{createdAt,title}`, `sheets` array, `charts:[]`, `pictureGraphs:[]`. Generate **one sheet**: the current loader reads only `sheets[0]`. A sheet has `id`, `name`, `cells` as row-major **string[][]**, optionally `rows`, `cols`, `formats`, `merges`. Numbers and formulas are strings: `"4"`, `"0.25"`, `"=SUM(B2:B3)"`. Do not send numbers, nulls, cell objects, or formula/value pairs in `cells`. Empty cells are `""`. Formulas are recalculated, not cached display values. Use native supported formulas and simple references; unsupported Excel functions do not become supported through JSON.

`rows` and `cols` are positive integers at least the data dimensions. Limits: 2,000 rows, 200 columns, 100,000 total cells (including allocated blanks). Formatting entries: `{row,col,format}` with zero-based indices. Valid format keys: booleans `bold,italic,underline,strikethrough,border,wrapText`; colors `textColor,backgroundColor` hex; `fontFamily` ≤100 characters; `fontSize` number 8–72; `align` left/center/right; `verticalAlign` top/middle/bottom; `numberFormat` plain/whole/decimal/currency/percent/thousands/scientific/date; integer `decimalPlaces` 0–10. A percent value of `"0.25"` formats as 25%.

A merge is `{row,col,rowSpan,colSpan}` with positive integer spans, entirely inside the allocated sheet. Merges cannot overlap. Only the top-left cell retains content; put `""` in covered cells. The native loader does not reconstruct charts or picture graphs from those root arrays; leave both empty and use GraphSplat for an AI-authored graph project.

## 4. ListSplat

**Open:** https://splatworks.org/splatworks/listsplat/  
**Filename example:** `classroom-library.listsplat.json`  
**Import:** File → Open .listsplat.json.

Exact marker `app:"ListSplatTM"`, numeric `version:1`; timestamps; `metadata:{title,author,className}` strings; `schema:{tables:[],relationships:[]}`; `layouts:[]`; `teacher:{studentView:false,notes:[],rubric:[]}`. A practical file needs at least one table, one field, a matching layout, and valid records.

Table: `{id,name,fields,records}`. Field: `{id,name,type,description,required,hidden}`. Allowed field types: `text,longText,number,currency,percent,date,time,dateTime,checkbox,rating,choice,multiSelect,email,phone,image,file,audio,link,calculation,autoNumber,createdAt,updatedAt`. Optional field properties: `options:string[]`, `formula:string`, `unique,primaryKey,readonly` booleans, `min,max,maxLength` numbers, `pattern` none/email/url/phone/custom, `customPattern,defaultValue,customMessage` strings. Do not invent a dropdown type or store choice labels as nested objects.

Record: `{id,createdAt,updatedAt,values:{FIELD_ID:VALUE}}`; values are string, number, boolean, or null. Keys in `values` are field IDs, not display names. Store numbers as numbers, checkboxes as booleans; dates `YYYY-MM-DD`, time `HH:MM`; multiSelect as comma-separated text. Native media fields require real supported data/URLs; bare filenames do not embed media. Optional record fields: `archived`, comments (`id,author,text,at,teacherOnly?`), history (`at,values`), rubricScores (criterion-ID → number).

Layouts: `{id,name,tableId,mode,locked}`; mode table/form/cards/gallery/list/kanban/calendar/labels/report. Optional fieldOrder, hiddenFieldIds are arrays of field IDs; columnWidths maps field IDs to numbers. Root `views` can be omitted; if supplied, each view has `id,name,tableId,mode,search,searchFieldId,find,sortKeys`; find is null or `{match:"all"|"any",rules:[{fieldId,operator,value,value2?}]}`, sortKeys entries `{fieldId,direction:"asc"|"desc"}`. Optional root rubricCriteria entries `{id,label,max}`.

Relationships point **from parent primary key to child foreign key**: `{id,name,fromTableId,fromFieldId,toTableId,toFieldId,enforceKeys:true,cardinality:"one-to-many"|"one-to-one"}`. Each table has at most one primaryKey; its values must be nonempty and unique. Parent types text/number/autoNumber; child type text or number matching the parent category; never an autoNumber FK. Every nonempty FK must match a parent record. One-to-one child keys cannot repeat. All table, field, record, relationship and layout references must resolve.

## 5. ShowSplat

**Open:** https://splatworks.org/splatworks/showsplat/  
**Filename example:** `water-cycle.showsplat.json`  
**Import:** File → Open .showsplat.json.

Root numeric `version:1`, `title`, `theme`, `footer`, `globalAudio:null` or an audio object, and nonempty `slides`. Safe themes violet/sky/forest/slate. Slide: `id,title,notes,bg,footer,audio,elements`; `bg:"light"` or `"section"`, `footer` boolean, `audio:[]`. Optional slide fields: `backgroundColor,footerColor,footerTextColor,defaultTextColor` CSS colors, hidden/collapsed booleans, indent integer 0–4. Speaker notes belong in `notes`.

Canvas geometry is **1600×900 pixels**, not the WebDeck 1280×720 authoring canvas. Each element has unique `id,type,x,y,w,h,z`. Types include `text,list,shape,table,image,video,link,html`. Safe text/list/shape fields: `text,fontFamily,fontSize,bold,italic,underline,color,fill,align` (left/center/right). List text uses newline-separated lines; a shape is a filled text-bearing box. ## Troubleshooting generated files

- **The app rejects the file:** check the exact app/type/schema marker, version type, extension, outer wrapper and required arrays/dictionaries. A schema description is not a project instance.
- **The file opens but some content is missing:** check unknown field names, unresolved IDs, importer filters and text limits. QuizSplat appends usable questions; GridSplat loads only the first sheet; ConceptSplat normalizes/drops invalid nodes/connectors; GraphSplat applies controls rather than top-level presentation data.
- **The layout differs:** check points versus pixels, text box dimensions, font availability and text flow. A successful parse does not certify page composition. Inspect the result and resave from the app.
- **Text lost styling:** WriteSplat uses ProseMirror node/mark names; LayoutSplat uses story text plus marks with UTF-16 offsets. Do not paste HTML into a field that expects a ProseMirror node tree or a plain story.
- **The planner rejects an otherwise sensible task list:** dictionaries, record IDs, _clock, _base and counter must agree. There is no unstamped simplified task-array JSON importer.
- **Media is missing:** VideoSplat JSON is a manifest; AudioSplat portable JSON needs real embedded audio; LayoutSplat and FontSplat need real supported embedded asset data. Metadata and invented base64 cannot recreate media.
