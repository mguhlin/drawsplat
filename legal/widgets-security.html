    Widget Security Boundary

    SplatWorks Component Data and Network Inventory

    Current deployment scope

    SplatWorks is the ecosystem; DrawSplat is the whiteboard. The ecosystem includes the five office apps, standalone creative and productivity tools, classroom widgets, and games. ConceptSplat, MarkdownSplat, DiagramSplat, QuizSplat, RubricSplat, and SketchSplat VR are current tool names; former names remain search aliases and existing URLs and project formats remain valid.

    Match this document to the components and services actually approved for your installation. Apps Script console controls apply to the DrawSplat whiteboard’s Drive/Sheets workflows; they do not automatically administer standalone app drafts or district MariaDB/MySQL records. See compliance and district review and the component data and network inventory.

    Updated October 15, 2026. Branding changes do not amend an existing signed agreement or expand the components, services, or data processing approved by a district. Templates and review packets are not executed agreements or compliance certifications.

    Districts and reviewers asked for a single page that answers: "What does each DrawSplatTM widget actually do with student data?" This page lists every widget and game served from the DrawSplatTM static site, what it stores, what external requests it makes, and what student data (if any) it collects.

    Widget Security Boundary — the short version

    Scope reviewed October 15, 2026. SplatWorks is a collection of applications with different storage, network, and permission behavior. Local editing does not mean the website makes no network requests or that user-created content cannot identify a student.

    • Loading public pages/assets sends request metadata to the host/CDN. The public sites use Cloudflare Pages. Self-hosted sites use the district’s chosen host.
    • Browser memory, localStorage, and IndexedDB serve different purposes. A draft may survive a tab close, contain student work, and remain until explicitly cleared. There is no ecosystem-wide 24-hour expiry.
    • Saved projects and exports can include imported documents, fonts, images, audio/video, quiz results, records, or other personal information. Clearing a browser draft does not erase downloaded, shared, cloud, or backup copies.
    • Existing file paths, browser storage identifiers, and native file formats keep their historical names for compatibility.

    Network egress declaration

    • Page and asset delivery: same-origin host/CDN requests and any app-specific external libraries, fonts, media, embeds, or user-entered remote resources expose request metadata to their source. Bundled third-party libraries keep their license notices; being bundled does not itself send project content to that library’s author.
    • Explicit connected actions: configured whiteboard backends, identity/roster providers, AI APIs, cloud file saving, QR/bot services, and user-selected external links have their own data flows. Disclose approved providers and data categories before student use.
    • Files and sharing: importing a local file or creating PPTX, ODP, animated GIF, PDF, image, or native project output runs locally in the supported export workflow. Browser/OS sharing passes a selected file to the chosen destination; that recipient’s handling is outside browser draft storage.
    • Security policy: CSP and permitted origins vary by application. Inspect the deployed headers and enabled features; documentation pages’ restrictive policy is not evidence that every app blocks all third-party origins.
    • Recording: camera, microphone, or screen permissions are component-specific and controlled by browser/device policy. Denying access can disable the selected capture feature; it does not disable local editing throughout the ecosystem.

    iframe / embed posture

    Embedding is not a separate privacy mode. Same-origin embeds can use the same origin’s storage, while browser policies may partition or restrict third-party storage. Parent/child handoffs are component-specific. Use the app’s documented embed link, restrict permissions to the features needed, and test the actual LMS/browser configuration. Do not place secrets or student records in query strings.

    Where this fits in the privacy story

    The Terms and Privacy Policy provide ecosystem commitments; this inventory describes implementation boundaries. The NDPA/DPA review packet, district addendum, and local notice builder must identify the approved components and optional services. Existing signed proposals/agreements keep their documented scope.
